## Знахідки
### F1 — Перша сторінка завжди пропускає перші `pageSize` рядків (off-by-one)
- Серйозність: high
- Правило: 7 / домовленість 7 (баг сторінкування, доведений на конкретних даних → high за кроком 7)
- Де: app/src/loans.js:32 (разом із дефолтом на рядку 30)
- Що не так: Дефолт `page = 1` (1-базовані сторінки), але зсув рахується як для 0-базованих: `const start = page * pageSize;`. Для `listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 })` це `all.slice(20, 40)` на 7 позиках → `items: []` при `total: 7`; на «3 000+ рядках» сторінка 1 віддасть рядки 21–40, а перші 20 позик недосяжні без `page: 0`, якого дефолт не передбачає.
- Як виправити: `const start = (page - 1) * pageSize;` (або зробити `page` 0-базованим із дефолтом `0` і зафіксувати це в CHANGELOG) і додати тест на `items`.
### F2 — `pageSize` без верхньої межі
- Серйозність: high
- Правило: 7 / домовленість 7
- Де: app/src/loans.js:30, 33
- Що не так: `{ page = 1, pageSize = 20 } = {}` і `all.slice(start, start + pageSize)` — розмір сторінки ніде не обрізається константою-максимумом; клієнт передасть `pageSize: 1e9` і отримає весь список, тобто новий необмежений список під виглядом сторінкового.
- Як виправити: додати `export const MAX_PAGE_SIZE = …` і `const size = Math.min(pageSize ?? 20, MAX_PAGE_SIZE);` перед `slice`.
### F3 — Нова експортована функція без запису в CHANGELOG
- Серйозність: high
- Правило: 6 / домовленість 6
- Де: app/CHANGELOG.md (відсутній у дифі); app/src/loans.js:30
- Що не так: У дифі є `+export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {})` з новою формою відповіді `{ items, page, pageSize, total }`, а `app/CHANGELOG.md` у дифі відсутній.
- Як виправити: додати в `app/CHANGELOG.md` запис у тому самому PR: `listLoansPage(db, user, { page, pageSize })` — сторінковий варіант `listLoans`, повертає `items`, `page`, `pageSize`, `total`.
### F4 — Новий тест не перевіряє `items` і проходить попри баг F1
- Серйозність: medium
- Правило: 8 / домовленість 8
- Де: app/test/loans.test.js:15–20
- Що не так: Тест звіряє лише `assert.equal(res.total, 7)`, `assert.equal(res.page, 1)`, `assert.equal(res.pageSize, 20)` — `page` і `pageSize` є відлунням переданих параметрів, а вміст сторінки `items` не перевіряється зовсім, тому тест зелений при `items: []`. Перевірено лише staff-шлях (`iryna`); member-шляху для `listLoansPage` (`olya` → `total: 3`, `items` з id `[1, 2, 7]`) нема.
- Як виправити: додати `assert.deepEqual(res.items.map((l) => l.id), [1, 2, 3, 4, 5, 6, 7])`, кейс із другою сторінкою (напр. `{ page: 2, pageSize: 5 }` → id `[6, 7]`) і виклик для `olya`.

## Дрібниці
- `listLoansPage` будує всю вибірку через `listLoans` (копія кожного рядка `({ ...l })`) і лише потім робить `slice` — для «3 000+ рядків» це та сама робота на сервері, що й раніше; меншою стає лише відповідь. Контекст, не знахідка.
- Нема валідації `page`/`pageSize` (припущення щодо серйозності): `page: -1, pageSize: 20` → `all.slice(-20, 0)` → `[]`; `pageSize: 0` → `[]`; нечислове значення → `slice(NaN, NaN)` → `[]` — мовчазно порожня сторінка замість помилки. Варто перевіряти `Number.isInteger(x) && x >= 1`.
- JSDoc `/** Paged variant for the staff UI … */` (loans.js:29) — функція доступна й учасникам (через фільтр у `listLoans`), коментар варто уточнити.
- Контекст: базові `listLoans`/`listMembers`/`overdueReport` без сторінок — борг бази, не знахідка цього PR.
